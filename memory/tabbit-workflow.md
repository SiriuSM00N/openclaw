## 🔄 Tabbit × OpenClaw 分工设计

### 核心原则

```
Tabbit = 信息收集层 + AI 处理层（14 模型调度）
OpenClaw = 自动化执行层 + 记忆存储 + 定时任务
```

### 能力对比

| 能力 | Tabbit | OpenClaw | 分工 |
|------|--------|----------|------|
| 浏览网页 | ✅ 原生 | ✅ 浏览器工具 | Tabbit（人工） |
| AI 对话 | ✅ 14 模型 | ❌ 仅 1 模型 | Tabbit |
| 多文档对比 | ✅ @标签页 | ❌ 需手动 | Tabbit |
| 文件读写 | ❌ 有限 | ✅ 完整 | OpenClaw |
| 定时任务 | ❌ 无 | ✅ Cron | OpenClaw |
| 记忆存储 | ❌ 临时 | ✅ MEMORY.md | OpenClaw |
| 消息推送 | ❌ 无 | ✅ 钉钉/多渠道 | OpenClaw |
| Agent 自动执行 | ✅ Pro 功能 | ✅ 子代理 | 两者结合 |

## 🛠️ 妙招库模板（5 个核心）

### 妙招 1：文章总结专家

```
请总结这些内容，按以下结构：

【核心论点】（1 句话，不超过 30 字）
【关键论据】（3-5 点，每点 1 句话）
【数据支撑】（如有具体数字，列出）
【行动建议】（对读者的实际建议）
【我的评价】（客观评价内容质量）

要求：
- 保持原文核心意思，不曲解
- 标注不确定的信息 [UNVERIFIED]
- 如有专业术语，括号内解释
- 输出格式：Markdown
```

**适用模型：** Gemini-3.1-Pro / Kimi-K2.5

---

### 妙招 2：多文档对比分析

```
@所有标签页

请从以下维度对比分析这些文档：

【维度 1：核心功能】
| 文档 | 功能描述 | 差异点 |
|------|---------|--------|
| A    | ...     | ...    |
| B    | ...     | ...    |

【维度 2：优缺点】
- 文档 A：优 [...]  缺 [...]
- 文档 B：优 [...]  缺 [...]

【维度 3：适用场景】
- 选 A 如果：...
- 选 B 如果：...

【综合建议】
...

要求：
- 每个结论必须标注来源（文档标题 + 段落）
- 如有矛盾信息，明确指出
- 用表格呈现核心对比
```

**适用模型：** Claude-Sonnet-4.6 / GPT-5.2
