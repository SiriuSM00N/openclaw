## 🐛 钉钉连接器无限重启 Bug

**问题：** 钉钉连接器陷入无限重启循环（auto-restart attempt 1/10 ~ 7/10）

**根本原因：**
- 两个独立的重启系统互相干扰
- Channel 自动重启（MAX_RESTART_ATTEMPTS=10）
- Health-Monitor 每小时重启 10 次，但会重置 Channel 计数器
- 结果：Channel 永远达不到 10 次，无限循环

**代码位置：** `gateway-cli-C2ZZYgwu.js:1709`

```javascript
// health-monitor 重启逻辑（错误）
channelManager.resetRestartAttempts(channelId, accountId);  // ❌ 重置计数器！
await channelManager.startChannel(channelId, accountId);
```

**临时修复：**
- 禁用 health-monitor：`channelHealthCheckMinutes: 0`
- Gateway 重启后生效

**永久修复：** 需要官方修复代码

## 🐛 Cron 任务重复触发 Bug（2026-03-12 11:41）

**问题：** 早安资讯任务在 11:39-11:41 期间被重复触发 4 次

**现象：**
- 11:39 首次触发 → 任务执行完成，消息已发送
- 11:40 第 2 次触发 → 重复
- 11:41 第 3 次触发 → 重复
- 11:41 第 4 次触发 → 重复

**根因：** 任务状态卡在 `runningAtMs`，导致 Cron 调度器认为任务还在运行，不断重试

**日志证据：**
```
State: {..., "runningAtMs": 1773286864242, "lastRunStatus": "ok"}
```

**临时修复：**
```bash
openclaw cron disable <jobId>
sleep 2
openclaw cron enable <jobId>
```

**影响：**
- 幸好没有重复发送消息（我检测到重复触发，主动拒绝执行）
- 否则用户钉钉会被 spam 4 条相同的消息

**待修复：** OpenClaw 官方需要修复 Cron 状态清理逻辑
