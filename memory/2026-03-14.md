## 📋 7 项检查触发机制（完整文档）

### 触发条件

**1. 用户反复质问（主要触发）**
- 用户对同一问题验证 ≥2 次
- 用户问"为什么还不行" / "怎么又失败了"
- 用户说"换个方法" / "再试试"
- **用户质疑我的回答**（如我说"没找到"，用户说"要啊"）

**2. 同一错误重复**
- 相同错误信息出现 ≥2 次
- 同一命令失败 ≥3 次
- 同一文件修改 ≥5 次

**3. 自我检测触发（主动）**
- 同一思路重复尝试 ≥3 次
- 工具使用率低（任务涉及外部信息但未调用搜索/日志）
- 准备说放弃言论（"我无法解决"等）
- 执行时间过长（>10 分钟无进展）

---

### 7 项检查清单

1. **逐字读错误** — 不是扫一眼，是逐字分析错误信息
2. **搜索同类问题** — WebSearch 关键词：`<错误信息> + OpenClaw`
3. **读相关日志** — `tail -100 /tmp/openclaw/openclaw-*.log`
4. **验证环境假设** — 权限/网络/版本是否真的有问题？
5. **反转假设** — 如果反过来想，根因可能是什么？
6. **查上下文 50 行+** — 日志前后文找关联线索
7. **检查隐藏关联错误** — 是否有级联失败？

---

### 执行流程

```
当触发条件满足时：
1. 🛑 立即停止当前思路 — 不要继续狡辩
2. 📋 执行 7 项检查清单 — 逐项验证
3. 📝 记录到当日日志 — 防止再犯
4. 💬 向用户汇报结果 — 诚实告知发现
```
