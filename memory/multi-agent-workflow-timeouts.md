## 🛠️ 超时处理策略

### 1. 分级超时

```typescript
// 第一级：标准超时
timeoutSeconds: 180

// 第二级：延长超时（重试时）
timeoutSeconds: 300

// 第三级：最大超时（关键任务）
timeoutSeconds: 600
```

### 2. 任务拆分

**大任务 → 小任务链**

```
架构设计（原 300s）
├── 1. 代码库探索（60s）
├── 2. 方案设计（120s）
└── 3. 输出文档（60s）
```

### 3. 渐进式交付

```typescript
// 子代理先返回中间结果
// 最终结果超时也能保留部分价值
```

### 立即行动
1. 检查子代理是否还在运行
2. 查看已返回的部分结果
3. 评估是否需要重试

## 📝 经验教训（2026-03-16）

### 教训
1. **GLM-5 架构设计给 2 分钟不够** — 需要搜索代码库、理解上下文
2. **代码修复也给 2 分钟太紧** — 需要理解上下文 + 修改 + 验证
3. **没有考虑网络延迟** — GitHub 推送失败

### 改进
1. ✅ 架构设计：120s → 300s
2. ✅ 代码修复：120s → 180s
3. ✅ 添加缓冲系数（1.5-2.5x）
4. ✅ 记录实际耗时用于未来优化
