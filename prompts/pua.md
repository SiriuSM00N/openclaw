# /pua — 失败检查清单触发命令

**触发方式：**

### 🟢 自动触发（主要方式）
- **用户反复质问同一个问题** — 当用户对同一问题验证 ≥2 次
- **同一错误重复出现** — 相同错误信息出现 ≥2 次
- **用户表达沮丧** — "你怎么又失败了" / "为什么还不行" / "换个方法"

### 🟡 手动触发（备用方式）
- 用户输入 `/pua`
- Cron 任务连续失败 ≥2 次（自动触发）

---

## 🦐 小虾米的 PUA 检查清单

当触发时，**立即停止当前思路**，强制执行以下检查：

### 1️⃣ 逐字读错误

不要扫一眼，是逐字分析错误信息：
- 错误关键词是什么？
- 错误发生在哪里（文件/行号/函数）？
- 错误的前后文是什么？

### 2️⃣ 搜索同类问题

WebSearch 关键词：
- `<错误信息> + OpenClaw`
- `<错误信息> + cron`
- `<错误信息> + 解决方案`

### 3️⃣ 读相关日志

```bash
tail -100 /tmp/openclaw/openclaw-*.log
```

查找：
- 错误发生前的最后操作
- 是否有级联错误
- 是否有隐藏的错误信息

### 4️⃣ 验证环境假设

逐项验证：
- [ ] 权限：真的有问题吗？`ls -la` 确认
- [ ] 网络：真的不通吗？`curl -v` 确认
- [ ] 版本：真的是版本问题吗？`--version` 确认
- [ ] 配置：配置真的加载了吗？读配置文件确认

### 5️⃣ 反转假设

如果反过来想：
- 如果不是权限问题，可能是什么？
- 如果不是网络问题，可能是什么？
- 如果错误信息是误导，真实原因可能是什么？

### 6️⃣ 查上下文 50 行 +

日志前后文找关联线索：
- 错误发生前 50 行在做什么？
- 错误发生后有什么异常？
- 是否有时间相关的模式？

### 7️⃣ 检查隐藏关联错误

- 是否有级联失败？
- 是否有其他任务也失败了？
- 是否有配置变更影响了多个地方？
